# 发布前的稳定性与体积检查

每次迭代先回归本次真实操作链路，再运行两种架构的完整 CI。模块集中增加后，
重新检查以下边界，记录具体问题、改动和证据，不以“整体通过”宣称没有缺陷。

- 截图／贴图：进入退出编辑、移动／边缘裁剪、跨屏倍率、撤销重做、复制保存、OCR 和关闭；导出必须与可见标注一致，异步结果不能复活旧窗口。
- 生命周期：快捷键、面板、网络发现、录屏、计时器和后台任务在关闭、停用、休眠及退出时释放；晚到结果失效。
- 性能：主线程不执行跨应用查询、转换、编码或整屏处理；任务单飞、队列和缓存有界。区分静态审查、隔离压力测试与真实桌面实测。
- 瘦身：核对实际运行入口、SwiftPM 编译源、打包资源和动态依赖；先确认无运行引用，再移除废弃实现。设计素材和测试工具不进入客户端。
- 分发：arm64／x86_64 各自验证真实二进制、上一版签名身份、DMG 内容和 OTA feed；发布后读回实际资产与签名。

旧实现仍用于隔离回归。macOS 14–26 的几何收纳与 macOS 27 的原生收纳均保留。
功能清单、图片素材和用户数据不因瘦身而删除。

自动化使用隔离偏好、命名剪贴板、离屏窗口及临时文件，不操作用户界面、不替用户升级。
