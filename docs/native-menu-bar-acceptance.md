# 原生菜单栏收纳，本地验收

应用内模块已接入 `MenuBarNativeShelf`，通过正常 OTA 交付。构建与状态检查不替代用户的真实操作验收。

## 实现边界

- 展开时释放收纳限制，实际图标留在系统菜单栏。原应用直接接收物理鼠标操作并绘制实时状态。
- 没有下方镜像抽屉、截图流、图标缓存、事件 tap、鼠标重放、点击次数解释或光标搬动。
- 仅被动观察输入，局部监听原样返回事件，移动事件合并；可见性变更和 AX 观察在输入回调返回后执行。AX 只观察，不执行菜单动作。
- 收纳名单按应用保存，系统决定原生图标顺序。按住 ⌘ 原生拖动后，仅观察松手的位置并读取当前菜单栏两次一致的真实容器布局，按苹果左右更新名单；设置正常时只展示一幅使用图；读取失败时才临时提供“重试”。
- 不按手势的意图坐标猜测最终落位，不合成拖动事件。位置不完整、布局仍变化、同应用图标跨两侧或存在重叠代理时避免误收纳；无法确认时保留持久名单，但本次取消自动收纳、保持原图标展开，并显示重试提示，不能再次应用旧名单。
- 点击菜单栏图标后保持展开；经确认的主菜单取消选中、Esc、其他应用标准窗口点击才释放交互状态。无法判断的自绘弹窗保持展开，直到明确退出操作。
- 任一屏幕菜单栏的预备区域都会先释放限制，减少系统其他状态项受到隐藏机制影响的机会。
- 隐藏仍依赖 macOS 27 的私有可见性接口；失效／超时恢复显示。原生重排速度、极快移入点击、刘海溢出、系统控制项及多屏真实体验仍需用户验收，不承诺系统限制已被消除。

## OTA 与用户验收

每次完成迭代和必要代码检查后发布正常 GitHub OTA。用户在安装版检查更新并安装，开发过程不操作用户界面、不替用户升级。0.1 正式版仍需用户确认。

1. 安装更新后，从原来的苹果进入收纳设置；原有应用收纳名单继续使用，无需清理数据。
2. 按住 ⌘，把原图标拖到我们的苹果左侧，松手后观察自动收纳；拖到右侧应恢复常驻。悬停苹果，直接操作展开后的系统原生图标。
3. 重点对比 VPN、微信等应用的原始单击、连续双击、右键、修饰键操作和实时流量，以及弹窗使用期间是否误收起。
4. 再检查首次从空名单拖入、拖动苹果本身、取消拖动、快速移入、反复开合、多屏和唤醒；同应用的多个图标请放在同一侧。

## 命令行检查

`zsh tools/run-native-menu-bar-regression.sh`：只使用假可见性接口和独立偏好域，覆盖生命周期、取消、晚到句柄、超时、保持展开和原生事件路径约束。不创建 AppKit 窗口，不发送输入，不实际隐藏用户图标。

构建、状态回归和签名校验不代表原生交互已通过用户验收。

事件入口回归必须经过 NSEvent 适配层验证按下、拖动和松开，不能只直接调用内部 CommandDragPhase。内部全部显示操作须取消未完成的归类读取与已入队拖动观察；晚到结果不得反转用户选择。设置常态不再提供这颗按钮。

多屏验收：在副屏把已收纳的微信拖到本屏苹果右侧，收起后微信仍常驻；另一个微信若留在左侧应继续收纳。切换屏幕重复，AppKit 仍返回另一屏苹果时也必须取实际松手的 native surface。原生跟踪未交付 mouseUp 时，释放 ⌘ 完成已观察到的拖动；晚到 mouseUp 不重复归类。

自动收起：鼠标离开所有菜单栏预备区域后等待 5 秒；重新移入取消倒计时，再次离开重新计时。拖动按住、原生菜单仍在使用、读取失败后的保守展开不由空闲倒计时强制打断。

## 每次收起的原生可见性保护

- 启动恢复、离开五秒、应用启停和手动收起都先读取两次一致的全部原生菜单栏；不能仅沿用上次拖动计算的名单。
- 任一屏幕苹果右侧的原生图标保护整个应用／辅助进程身份组；识别不出归属或分界时保持展开。补全 NSWorkspace 名单外的菜单栏辅助进程及其外层 app 标识，避免允许列表遗漏。
- 只有确认全在左侧且已选择收纳的应用身份组进入隐藏范围。已有原生限制的替换复用上次已核验的隐藏身份组，不为无关应用启停整栏闪动。
- 系统激活返回成功后仍检查保留图标：两次确认其各屏幕原生节点仍在；收起前确实可命中的原图标，收起后还须按新位置命中同一 PID。窗口 ID 重建不等于图标丢失。辅助功能树可能保留已隐藏／溢出的逻辑节点，不能将待收纳 PID 仍在 AXChildren 中误判为隐藏失败；不宣称能据节点是否存在证明实际渲染消失。
- 核验失败、超时、权限变化、未知归属立即释放限制并停止自动重试；设置页只在需要时显示真实问题。悬停／拖动／停用取消旧核验，晚到结果不能重新隐藏图标。没有录屏、事件重放或空闲轮询。
- 实机验收由用户更新后执行，重点覆盖两个微信、VPN、菜单栏辅助进程、多屏左右不一致以及不重新拖动的旧名单恢复。状态回归和打包检查不替代这一验收。

真实只读元数据回归：空的 AXChildren 可返回 AXError.noValue（-25212），应按空数组处理；不能将其误报为全量布局不完整。超时、拒绝访问、其他 AX 错误仍使快照不完整。本轮本机读取在相同 24 个原生容器下，由 incomplete 改为 complete，收纳保护计划可解析；未激活隐藏限制或操作用户界面。


## 0.0.125：修复核验误退回

安装版 0.0.124 日志显示三次 postflight failed 后释放收纳限制。只读元数据进一步确认：本屏多个不同 PID 的节点重叠在相同右端位置，而系统按实际 z-order 命中的是另一个 PID；副屏节点则可独立命中。AXChildren 存在不代表当前渲染可见，旧版“只要隐藏 PID 的节点仍存在就失败”的条件无效，现已移除。

保留每次收起前的跨屏右侧身份保护与原生激活失败回退；新增只读 AXUIElementCopyElementAtPosition 基线。收起前确实可命中的保留图标，在收起后的最新位置也必须命中原 PID；已溢出或不支持 hit-test 的节点不虚构“原来可见”基线，但其允许标识和原生节点仍受保护。核验最多六次且总窗口 1.8 秒，须连续两次通过；整体看门狗五秒，取消／悬停／停用丢弃晚到结果。不移动鼠标、不发送事件、不调用菜单动作、不取图。

命令行只验证元数据、回归与包；真正收起及原生交互仍由用户 OTA 后验收。


## 0.0.127：一次失败不能永久取消自动收起

安装版 0.0.126 的错误日志与源码共同确认：failConcealment 将 wantsCollapsed 清为 false，普通悬停和离开无法恢复。只读检查随后连续四次读到完整的 24 个容器、稳定布局及 8 个可收纳应用；这证明当前条件已恢复，却没有再触发收起。未操作用户界面或改变收纳名单。

本轮保留用户意图，单独暂停失败尝试。重新进入菜单栏再离开、实际环境通知或明确重试后，重新核验并启动五秒收起；普通区域移动不反复重试。主动全部显示和失败的拖动归类仍保持不自动收纳。前置读取最多四次／2.4 秒；同侧流量宽度变化不再要求像素相同，跨苹果、保护集合变化或不完整读取仍拒绝。收起后的右侧命中保护、取消和失败恢复均保留。实际原生收起效果由用户 OTA 后验收。

启动时若尚未应用任何隐藏限制便前置读取失败，保留一次五秒后的新读取机会；最多一次，悬停、全部显示、停用和新代次会取消。真实隐藏后的保护失败不做定时重试。
