# 原生菜单栏收纳，本地验收

应用内模块已接入 `MenuBarNativeShelf`，通过正常 OTA 交付。构建与状态检查不替代用户的真实操作验收。

## 实现边界

- 展开时释放收纳限制，实际图标留在系统菜单栏。原应用直接接收物理鼠标操作并绘制实时状态。
- 没有下方镜像抽屉、截图流、图标缓存、事件 tap、鼠标重放、点击次数解释或光标搬动。
- 仅被动观察输入，局部监听原样返回事件，移动事件合并；可见性变更和 AX 观察在输入回调返回后执行。AX 只观察，不执行菜单动作。
- 收纳名单按应用保存，系统决定原生图标顺序。按住 ⌘ 原生拖动后，仅观察松手的位置并读取当前菜单栏两次一致的真实容器布局，按苹果左右更新名单；设置正常时只展示一幅使用图；读取失败时才临时提供“重试”。
- 不按手势的意图坐标猜测最终落位，不合成拖动事件。位置不完整、布局仍变化、同应用图标跨两侧或存在重叠代理时避免误收纳；无法确认时保留原设置并显示重试提示。
- 点击菜单栏图标后保持展开；经确认的主菜单取消选中、Esc、其他应用标准窗口点击才释放交互状态。无法判断的自绘弹窗保持展开，直到明确退出操作。
- 任一屏幕菜单栏的预备区域都会先释放限制，减少系统其他状态项受到隐藏机制影响的机会。
- 隐藏仍依赖 macOS 27 的私有可见性接口；失效／超时恢复显示。原生重排速度、极快移入点击、刘海溢出、系统控制项及多屏真实体验仍需用户验收，不承诺系统限制已被消除。

## OTA 与用户验收

每次完成迭代和必要代码检查后发布正常 GitHub OTA。用户在安装版检查更新并安装，开发过程不操作用户界面、不替用户升级。0.1 正式版仍需用户确认。

1. 安装更新后，从原来的苹果进入收纳设置；原有应用收纳名单继续使用，无需清理数据。
2. 按住 ⌘，把原图标拖到我们的苹果左侧，松手后观察自动收纳；拖到右侧应恢复常驻。悬停苹果，直接操作展开后的系统原生图标。
3. 重点对比 VPN、微信等应用的原始单击、连续双击、右键、修饰键操作和实时流量，以及弹窗使用期间是否误收起。
4. 再检查首次从空名单拖入、拖动苹果本身、取消拖动、快速移入、反复开合、多屏和唤醒；同应用的多个图标请放在同一侧。

## 命令行检查

`zsh tools/run-native-menu-bar-regression.sh`：只使用假可见性接口和独立偏好域，覆盖生命周期、取消、晚到句柄、超时、保持展开和原生事件路径约束。不创建 AppKit 窗口，不发送输入，不实际隐藏用户图标。

构建、状态回归和签名校验不代表原生交互已通过用户验收。

事件入口回归必须经过 NSEvent 适配层验证按下、拖动和松开，不能只直接调用内部 CommandDragPhase。内部全部显示操作须取消未完成的归类读取与已入队拖动观察；晚到结果不得反转用户选择。设置常态不再提供这颗按钮。
